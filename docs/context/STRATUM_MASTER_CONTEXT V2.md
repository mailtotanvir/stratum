
# STRATUM_MASTER_CONTEXT.md

## Project Identity

Stratum is a local-first AI-assisted engineering runtime workstation.

Primary goals:
- deterministic execution
- repository transformation
- human-approved operations
- provider-agnostic workflows
- cheap/free model leverage
- extensibility without framework lock-in

---

# Core Philosophy

Stratum is NOT:
- an AGI platform
- an autonomous swarm system
- a proprietary agent ecosystem

Stratum IS:
- a runtime substrate
- a harness engineering platform
- a repository transformation workstation
- a composable AI engineering runtime

---

# Runtime First

The runtime owns:
- execution
- approvals
- events
- logs
- artifacts
- persistence

Agent systems are optional layers ABOVE the runtime.

---

# Adapter First

Prefer:
- adapters
- connectors
- standards compatibility

Avoid:
- proprietary orchestration frameworks
- custom DSLs
- tightly coupled abstractions

---

# Standards Compatibility

Preserve compatibility with:
- OpenAI-compatible APIs
- MCP
- Codex ecosystems
- Claude ecosystems
- CAMEL
- AutoGen
- CrewAI
- LangGraph
- Ollama
- OpenRouter
- VSCode extensions
- TUI interfaces
- Telegram runtimes
- future open-source memory systems

---

# Memory Philosophy

Memory belongs to:
- runtime infrastructure

NOT:
- individual agents/models

MVP memory includes:
- tasks
- events
- logs
- artifacts
- repo summaries
- approvals

Future memory systems should integrate via adapters.

---

# Repository Transformation Focus

Stratum is fundamentally a:

Repository Transformation Runtime.

Example transformations:
- Electron → Tauri
- SaaS → local-first
- remove enterprise orchestration
- simplify multi-user systems
- remove telemetry
- replace cloud APIs with local inference

---

# Runtime Event Philosophy

All important runtime actions emit structured events.

Examples:
- task_started
- repo_scanned
- plan_generated
- approval_requested
- command_executed
- artifact_created

Event streams become:
- observability substrate
- memory substrate
- orchestration substrate

---

# Final Guiding Principle

Build:
- stable runtime foundations
- clean interfaces
- observable systems
- extensible boundaries

Avoid:
- hype architecture
- fake autonomy
- ecosystem isolation
