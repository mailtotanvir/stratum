# v0.6.0 Runtime Query Observability Release Readiness

## Summary

v0.6.0 establishes Stratum's runtime query observability foundation. It turns
runtime events, projection contracts, lineage reconstruction, governance audit
records, analytics, intelligence, explainability, and provider/cost telemetry
into deterministic read-only operator views.

The Runtime Event Store remains the source of truth. Projections and summaries
remain rebuildable derived state.

## Major Capabilities

- Runtime query framework, execution diagnostics, query history, query
  reconstruction, query verification, query lineage, query manifests, and
  query snapshot export.
- Projection framework, projection lifecycle management, rebuild diagnostics,
  replay analytics, verification, lineage, manifests, snapshot export, and
  drift detection.
- Governance audit projection with approval, rejection, policy evaluation,
  reflection, and budget action summaries.
- Decision lineage reconstruction with evidence links, parent decision chains,
  orphan detection, and deterministic ordering.
- Artifact lineage projection with artifact provenance, proposal/decision/tool
  links, parent artifact chains, and incomplete lineage reporting.
- Runtime reconstruction views for sessions, timelines, decisions, artifacts,
  tools, proposals, governance decisions, and health consistency.
- Operational analytics for sessions, events, proposals, decisions, artifacts,
  tool executions, governance, projections, reconstruction, and trends.
- Runtime intelligence summaries for health, projection integrity, governance,
  reconstruction completeness, risks, and recent high-signal activity.
- Explainability views for decisions, artifacts, and sessions.
- Projection Registry v2 with projection contracts and capability metadata.
- Provider and cost observability for provider/model usage, latency, tokens,
  and estimated costs when metadata is available.

## Architecture Guarantees

- The Runtime Event Store is authoritative for observed runtime behavior.
- Runtime Session State and existing persisted domain records remain canonical
  where they already own state.
- Projections are derived and rebuildable.
- Analytics, intelligence, explainability, provider observability, manifests,
  exports, and dashboards are request-scoped derived views.
- Operator reads may emit diagnostics, but derived view payloads do not become
  authoritative state.
- Diagnostic self-counting is avoided where summaries could otherwise inflate
  their own metrics.
- Ordering is deterministic for registry entries, lineage records, trend
  buckets, risk summaries, activity summaries, provider reports, and model
  usage summaries.

## Non-Goals

- No provider routing changes.
- No provider API calls or billing API calls.
- No LLM-based summarization.
- No memory systems.
- No graph databases.
- No persistent projection payload storage.
- No automatic projection repair.
- No automatic governance remediation.
- No schema churn for historical runtime events.
- No external dependencies.

## Known Limitations

- Provider cost values are estimates based only on metadata already present in
  runtime events.
- Provider observability does not normalize pricing tables or query provider
  billing systems.
- Projection Registry v2 is a contract and capability registry; the existing
  builder registry remains the execution registry.
- Explainability depends on available lineage, governance, artifact, and
  reconstruction evidence. Missing related evidence produces incomplete
  explanations, not repaired history.
- Runtime intelligence uses deterministic rules rather than learned or
  LLM-generated analysis.
- Several route aliases remain for backward compatibility.

## Remaining Known Risks

- Future provider integrations must consistently emit provider/model/token
  metadata to make provider observability complete.
- As projection count grows, contract metadata should be reviewed for naming
  and capability taxonomy consistency.
- More end-to-end fixture scenarios may be useful before provider routing or
  multi-provider execution is introduced.
